## 📄 문제

동네 마트에서 **무료행사**를 진행합니다.
진열된 상품 중 **서로 다른 2개**를 골랐을 때, 두 상품 가격의 합이 `k`원 **이하**이면 두 상품을 모두 무료로 가져갈 수 있습니다.

손님은 기왕이면 **가격 합이 가장 큰** 조합을 가져가고 싶어 합니다.

상품 가격이 담긴 정수 배열 `prices`와 행사 한도 금액 `k`가 주어질 때,
무료로 가져갈 수 있는 두 상품 가격 합의 **최댓값**을 return 하도록 solution 함수를 완성해 주세요.
조건을 만족하는 조합이 하나도 없다면 `-1`을 return 합니다.

### 제한사항

- 2 ≤ `prices`의 길이 ≤ 1,000
- 1 ≤ `prices`의 원소 ≤ 1,000,000
- 1 ≤ `k` ≤ 2,000,000
- 같은 가격의 상품이 여러 개 있을 수 있으며, 서로 다른 상품이면 가격이 같아도 함께 고를 수 있습니다.

### 입출력 예

| prices | k | result |
| --- | --- | --- |
| [8, 3, 6, 1, 9, 4] | 12 | 12 |
| [5, 7, 10] | 11 | -1 |
| [3, 9, 6, 2] | 10 | 9 |
| [2, 2, 2] | 4 | 4 |

### 입출력 예 설명

**입출력 예 #1**
- 8 + 4 = 12 로 한도 12원에 딱 맞습니다. 이보다 큰 합은 한도를 넘으므로 12를 return 합니다.

**입출력 예 #2**
- 가장 싼 두 상품 5 + 7 = 12 도 한도 11원을 넘으므로 -1을 return 합니다.

**입출력 예 #3**
- 합이 10이 되는 조합은 없고, 3 + 6 = 9 가 가장 큽니다.

**입출력 예 #4**
- 가격이 같은 서로 다른 상품 두 개(2 + 2)를 고를 수 있습니다.

## 💭 접근 방법

1. 문제 요약: 배열에서 두 원소를 골라 합이 `k` 이하인 것 중 최댓값 찾기
2. 제약조건 → 허용 시간복잡도: N ≤ 1,000 → O(N²) = 약 50만 번 → **완전탐색으로 충분** ✅
3. 떠올린 방법
    - 완전탐색: 이중 for문으로 모든 쌍 `(i, j)` (i < j)을 확인하며 `합 ≤ k`인 것 중 최댓값 갱신 → O(N²)
    - 최적화 (N이 10만이라면?): 정렬 후 **투 포인터** → O(N log N) (아래 참고)
4. 사용한 자료구조 / 알고리즘: 완전탐색 (이중 반복문)

### 🔍 포인트

- `j`를 `i + 1`부터 시작해야 **같은 상품을 두 번 고르는 실수**와 **중복 조합 검사**를 동시에 막을 수 있다.
- 정답이 없을 때를 위해 `answer`를 `-1`로 초기화해 두면 따로 처리할 필요가 없다.
- 최대 합은 1,000,000 × 2 = 2,000,000 → `int` 범위 안이라 오버플로 걱정 없음.

### ➕ 더 나아가기 — 투 포인터 O(N log N)

```java
Arrays.sort(prices);
int left = 0, right = prices.length - 1;
int answer = -1;
while (left < right) {
    int sum = prices[left] + prices[right];
    if (sum <= k) {
        answer = Math.max(answer, sum);   // 조건 만족 → 기록하고 합을 키워 본다
        left++;
    } else {
        right--;                          // 한도 초과 → 합을 줄인다
    }
}
return answer;
```

## ⏱️ 복잡도

- 시간: O(N²) (투 포인터: O(N log N))
- 공간: O(1)
