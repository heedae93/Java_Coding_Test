# ⏱️ 시간복잡도 (Time Complexity)

## 1. 시간복잡도란?

알고리즘이 **입력 크기 N에 따라 얼마나 많은 연산을 수행하는지**를 나타내는 척도.

실제 실행 시간(초)은 컴퓨터 성능이나 언어에 따라 달라진다.
그래서 시간 대신 **연산 횟수가 N에 따라 어떻게 늘어나는지**로 비교한다.

> 💡 **코테에서 시간복잡도를 따지는 이유**
> 문제를 풀기 **전에** "이 방법으로 시간 안에 통과할 수 있을까?"를 판단하기 위해서

---

## 2. 점근 표기법

| 표기 | 의미 | 설명 |
| --- | --- | --- |
| **Big-O (O)** | 상한 (최악의 경우) | "아무리 느려도 이 정도" |
| Big-Omega (Ω) | 하한 (최선의 경우) | "아무리 빨라도 이 정도" |
| Big-Theta (Θ) | 평균 (상한 = 하한) | "딱 이 정도" |

> 📌 코테·실무에서는 **최악의 경우 기준인 Big-O**를 주로 쓴다. 최악의 입력에서도 통과해야 하기 때문.

---

## 3. Big-O 계산 규칙

### 규칙 1. 상수는 버린다

```
3N + 5     → O(N)
100        → O(1)
```

### 규칙 2. 가장 큰 항만 남긴다

```
N² + 3N + 10   → O(N²)
N log N + N    → O(N log N)
```

N이 커질수록 가장 큰 항이 전체를 지배하기 때문.

### 규칙 3. 순차 실행은 더하고, 중첩은 곱한다

```java
for (int i = 0; i < N; i++) { ... }     // O(N)
for (int j = 0; j < M; j++) { ... }     // O(M)
// 전체: O(N + M)

for (int i = 0; i < N; i++) {
    for (int j = 0; j < M; j++) { ... }
}
// 전체: O(N × M)
```

### 규칙 4. 서로 다른 입력은 다른 변수로

배열 두 개의 길이가 다르면 O(N²)가 아니라 **O(N × M)**

## 4. 주요 시간복잡도와 예시

> **O(1) < O(log N) < O(N) < O(N log N) < O(N²) < O(N³) < O(2ᴺ) < O(N!)**

### O(1) — 상수 시간

입력 크기와 상관없이 항상 일정.

```java
int x = arr[5];          // 배열 인덱스 접근
map.get(key);            // HashMap 조회 (평균)
```

### O(log N) — 로그 시간

매 단계마다 탐색 범위가 **절반씩 줄어듦**.

```java
// 이분 탐색
int lo = 0, hi = N - 1;
while (lo <= hi) {
    int mid = (lo + hi) / 2;
    if (arr[mid] == target) return mid;
    else if (arr[mid] < target) lo = mid + 1;
    else hi = mid - 1;
}
```

N = 10억이어도 약 30번이면 끝난다.

### O(N) — 선형 시간

데이터를 한 번씩 훑는다.

```java
int sum = 0;
for (int i = 0; i < N; i++) sum += arr[i];
```

### O(N log N) — 선형 로그 시간

효율적인 정렬 알고리즘의 시간.

```java
Arrays.sort(arr);        // 병합 정렬, 퀵 정렬, 힙 정렬
```

> 📌 "정렬이 들어가면 최소 O(N log N)"으로 기억

### O(N²) — 이차 시간

이중 반복문으로 모든 쌍을 확인.

```java
for (int i = 0; i < N; i++)
    for (int j = i + 1; j < N; j++)
        if (arr[i] + arr[j] == target) count++;
```

버블 정렬, 선택 정렬, 삽입 정렬이 해당.

### O(N³) — 삼차 시간

삼중 반복문. 플로이드-워셜이 대표적.

### O(2ᴺ) — 지수 시간

각 원소를 "넣는다/안 넣는다"로 모든 부분집합 확인.

```java
// 메모이제이션 없는 피보나치
int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
}
```

### O(N!) — 팩토리얼 시간

모든 순열을 확인. N = 10만 넘어도 매우 느려진다.

## 5. N 크기별 연산 횟수 비교

| N | log N | N log N | N² | 2ᴺ |
| --- | --- | --- | --- | --- |
| 10 | 3 | 33 | 100 | 1,024 |
| 100 | 7 | 664 | 10,000 | 약 10³⁰ |
| 1,000 | 10 | 약 1만 | 100만 | 계산 불가 |
| 100,000 | 17 | 약 170만 | 100억 | 계산 불가 |
| 1,000,000 | 20 | 약 2,000만 | 1조 | 계산 불가 |

## 6. ⭐ 코테 핵심: N 크기로 알고리즘 역추적하기

> 💡 **1초에 약 1억(10⁸) 번 연산**이 기준 (자바는 조금 여유 있게 잡기)

문제의 **N 범위를 보고 허용되는 시간복잡도를 먼저 정하면** 쓸 수 있는 알고리즘이 좁혀진다.

| N 범위 | 허용 시간복잡도 | 떠올릴 알고리즘 |
| --- | --- | --- |
| N ≤ 10 | O(N!) | 순열 완전탐색 |
| N ≤ 20 | O(2ᴺ) | 부분집합, 비트마스크 |
| N ≤ 500 | O(N³) | 플로이드-워셜, 3중 반복 |
| N ≤ 5,000 | O(N²) | 2중 반복, 간단한 DP |
| N ≤ 100,000 ~ 1,000,000 | O(N log N) | 정렬, 이분탐색, 힙, 다익스트라 |
| N ≤ 10,000,000 | O(N) | 투 포인터, 누적합, 해시 |
| N > 10⁸ | O(log N), O(1) | 이분탐색, 수학 공식 |

**예시**

- N = 100,000인데 이중 for문 O(N²) → 100억 번 → ❌ 시간 초과
- 같은 문제를 정렬 + 이분탐색 O(N log N)으로 → 약 170만 번 → ✅ 통과

## 7. 공간복잡도 (Space Complexity)

알고리즘이 사용하는 **메모리 양**.

| 코드 | 공간복잡도 |
| --- | --- |
| 변수 몇 개 | O(1) |
| `int[] arr = new int[N]` | O(N) |
| `int[][] dp = new int[N][M]` | O(N × M) |
| 재귀 깊이 N | O(N) (호출 스택) |

> 📌 **메모리 기준**: `int` 1개 = 4바이트
> `int[1000만]` ≈ 40MB / `int[1만][1만]` ≈ 400MB → 보통 메모리 제한(256MB) 초과

---

## 8. ⚠️ 자바에서 자주 하는 시간복잡도 실수

| 실수 | 실제 복잡도 | 해결 |
| --- | --- | --- |
| 반복문 안에서 `str += "a"` | O(N²) (매번 새 문자열 생성) | `StringBuilder` 사용 |
| `ArrayList.remove(0)` 반복 | 매번 O(N) | `ArrayDeque.poll()` (O(1)) |
| `ArrayList.contains(x)` 반복 | 매번 O(N) | `HashSet.contains(x)` (O(1)) |
| `Scanner`로 대량 입력 | 느림 | `BufferedReader` 사용 |
| `System.out.println` 반복 출력 | 느림 | `StringBuilder`에 모아 한 번에 출력 |
| 메모이제이션 없는 재귀 | O(2ᴺ) | DP 배열로 저장 |

## 9. 자바 컬렉션 연산별 시간복잡도

| 컬렉션 | 추가 | 삭제 | 조회·탐색 |
| --- | --- | --- | --- |
| `ArrayList` | 끝 O(1), 중간 O(N) | 끝 O(1), 중간 O(N) | `get(i)` O(1), `contains` O(N) |
| `LinkedList` | 양끝 O(1) | 양끝 O(1) | `get(i)` O(N) |
| `ArrayDeque` | 양끝 O(1) | 양끝 O(1) | - |
| `HashMap` / `HashSet` | O(1) | O(1) | O(1) |
| `TreeMap` / `TreeSet` | O(log N) | O(log N) | O(log N) |
| `PriorityQueue` | O(log N) | `poll` O(log N) | `peek` O(1) |
| `Arrays.sort` / `Collections.sort` | - | - | O(N log N) |
